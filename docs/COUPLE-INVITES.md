# 커플 초대와 같은 집

기준: 01-product-and-screens.txt 2·3절, 02-development-design.txt 2·3·5절, 03-operations-and-demo.txt 별도 검증 항목.

## 화면과 연결

- 가입 직후에는 집이 없습니다. 새 집을 만들거나 받은 초대 코드를 입력합니다.
- 혼자 사는 집에서는 7자리 영문 대문자/숫자 코드를 발급·복사할 수 있습니다. 24시간 유효하고 한 번만 사용합니다.
- 재발급하면 이전 미사용 코드는 무효화합니다. 초대 취소도 가능합니다.
- 코드 확인 단계는 데이터를 변경하지 않습니다. 상대방 표시명과 기존 방 삭제 여부를 보여줍니다.
- 기존 집이 있으면 “기존의 방은 삭제됩니다. 초대를 수락하시겠습니까?” 확인 후에만 수락합니다.
- 수락 성공 시 이전 집·가구·부착물·초대 코드는 삭제되고 상대방 집으로 이동합니다. 취소·실패는 기존 집을 유지합니다.
- 연결 후 두 사람의 프로필(공개 표시명·가입일)과 연결일을 보여줍니다. 이메일·비밀번호는 보내지 않습니다. 초대 UI는 숨깁니다.
- 두 멤버 모두 같은 집을 보고 각자 수정할 수 있습니다. 실시간 동기화/공동 편집 잠금은 이번 범위에서 제외했습니다. 최신 집 불러오기나 화면 재진입으로 변경을 확인합니다. 이전 revision 수정은 기존 충돌 처리로 거절됩니다.
- 연결 해제와 다른 커플로 전환은 문서처럼 제공하지 않습니다.

## DB와 권한

V3 마이그레이션은 기존 houses.owner_id를 house_members로 옮긴 뒤 owner_id를 제거합니다. 기존 집 ID·가구·revision은 보존합니다.

- house_members: account_id PK(한 계정은 한 집), house_id FK, joined_at, last_seen_revision.
- invites: id, code UNIQUE, house_id FK, issued_by, expires_at, consumed_at, revoked_at.
- 집 행을 잠근 트랜잭션에서 인원 2명 제한, 코드 만료/사용/취소, 발급자의 현재 소속과 수락자의 기존 소속을 다시 검증합니다.
- 수락 요청은 미리보기 당시 existingHouseId와 agreeDelete를 전달합니다. 미리보기 이후 소속이 바뀌면 다시 확인하도록 거절합니다.
- 계정·집 잠금은 ID 정렬 순서로 획득합니다. 기존 집 삭제, 새 멤버 등록, 코드 사용 처리는 하나의 트랜잭션입니다.
- 집 조회/편집은 세션 계정으로 현재 멤버십을 확인합니다. 편집 트랜잭션 내부에서도 집 잠금 후 재검증하여 오래된 세션이 이전 집을 수정하지 못합니다.
- 공개 집 방문은 아직 구현하지 않았습니다. 현재는 본인/커플의 집만 조회합니다.

## API

GET /api/couple, POST /api/houses, POST·DELETE /api/houses/{id}/invite, POST /api/invites/preview, POST /api/invites/accept.
로그인은 집을 새로 만들지 않고 현재 멤버십을 반환합니다. 상태 변경은 CSRF 토큰이 필요합니다.

## 검증과 배포

CoupleFlowTest에서 정상 연결·집 없는 수락·삭제 동의·재로그인·두 사람 편집·제3자 차단·코드 만료/취소/재발급·동시 수락·DB 오류 시 삭제 롤백을 검사합니다.
실제 PostgreSQL은 별도 검증 DB에서 V2 기존 집 → V3 마이그레이션, 브라우저 2계정 연결, 앱 재시작 후 복원을 확인합니다.

V3는 기존 코드가 사용하던 owner_id 컬럼을 제거하므로 배포 전략은 Recreate입니다. 구버전 Pod가 종료된 뒤 신버전이 마이그레이션합니다. 배포 중 잠깐 접속이 끊기고 재로그인이 필요합니다. V2 이미지로 단순 롤백할 수 없으며 DB 스키마와 함께 복구해야 합니다.
