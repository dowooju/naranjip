# 샘플 집과 계정

나란집 앱은 처음 켜질 때 구경용 샘플 집 4채를 자동으로 만듭니다. 이미 있으면 다시 만들지 않으므로 앱이나 DB 컨테이너를 재시작해도 중복되지 않습니다. DB 볼륨이 유지되는 한(`docker compose down -v`를 하기 전까지) 계속 남습니다.

| 기획 | 아이디(거주자 이름) | 집 | 일반 하트 | 방명록 |
| --- | --- | --- | --- | --- |
| S1 / H1 | 햇살방 | 문·러그·식탁·의자 2·냉장고(쪽지 공개 1, 비공개 1)·소파·큰 화분 | 3 (S2·S3·S4) → 1위 | S2가 작성 |
| S2 / H2 | 구름집 | 작은 화분·책상(액자 1)·의자·세운 소파·러그·왼쪽 벽 문 | 2 (S1·S3) → 2위 | S3가 작성 |
| S3 / H3 | 달빛집 | 화분 2·냉장고(공개 쪽지)·러그·소파·의자·책상 | 1 (S1) → 공동 3위 | S4가 작성 |
| S4 / H4 | 솔바람집 | 문·식탁·의자 2·화분 2 | 1 (S2) → 공동 3위 | S1이 작성 |

- **이번 주 콘셉트**: 관리자가 아직 콘셉트를 등록하지 않은 상태라면 "비 오는 날의 집"을 열고, 달빛집에 콘셉트 하트 3개(S1·S2·S4)를 넣어 일반 순위와 다른 1위를 만듭니다. 이미 콘셉트가 진행 중이면 그 콘셉트는 건드리지 않습니다.
- 샘플 계정은 관리자가 아닙니다. 이메일은 `s1@sample.naranjip.local` 형식입니다.
- 가구는 실제 배치 규칙(경계·겹침·벽·부착)을 그대로 거쳐 놓습니다.

## 샘플 계정으로 로그인하려면

`SAMPLE_PASSWORD`가 없으면 아무도 모르는 무작위 비밀번호가 되어 구경 전용 계정이 됩니다. 로그인하려면 프로젝트 폴더의 `.env` 파일에 비밀번호를 적고 앱을 다시 띄웁니다. 8자 이상으로 정하고, 실제로 쓰는 비밀번호는 재사용하지 마세요.

```bash
cp .env.example .env
```

`.env`에서 `SAMPLE_PASSWORD=` 뒤에 비밀번호를 적은 뒤:

```bash
docker compose up -d
```

환경변수가 바뀐 앱 컨테이너만 다시 만들어집니다. DB 데이터는 그대로입니다. `.env`는 Git에 올라가지 않습니다. 공개 서버에서는 샘플 계정으로 누구나 로그인할 수 있게 되므로 시연할 때만 설정하세요.

- 샘플이 아직 없으면 이 비밀번호로 만들어집니다.
- 샘플이 이미 있으면 계정을 지우지 않고 **샘플 계정 네 개의 비밀번호만** 이 값으로 바뀝니다. 앱이 켜질 때마다 맞춰 주므로, 다른 비밀번호로 바꿀 때도 `.env`를 고치고 `docker compose up -d`를 다시 실행하면 됩니다. `SAMPLE_PASSWORD`를 다시 비우면 마지막으로 설정한 비밀번호가 그대로 남습니다.
- 샘플 아이디와 샘플 이메일(`s1@sample.naranjip.local` 등)이 모두 맞는 계정만 바꾸므로, 같은 이름의 일반 회원은 영향을 받지 않습니다.

## 끄기

`.env`에 `SAMPLE_DATA=false`를 넣으면 샘플을 만들지 않습니다. 이미 만들어진 데이터는 지우지 않습니다. 테스트 환경은 기본으로 꺼져 있고, `SampleDataTest`만 별도 DB에서 켜서 검증합니다.

구현: `src/main/java/com/naranjip/infrastructure/SampleDataSeeder.java`
